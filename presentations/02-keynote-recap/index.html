The Keynote Recap's Core Thesis
Over 40% of all newly created pull requests across GitHub now start with an AI agent's initial draft. Software delivery has fundamentally inverted: human engineers are spending more time reviewing, governing, and orchestrating architectural intent than manually typing syntax.
The recap video begins with the sheer scale of the platform today: 225 million developers, over 34 billion commits, and 45 billion Actions executions. Feature Announcement #1

Copilot Fusion (GA)

Intelligent multi-model routing engine

What Was Announced
  • General Availability: Copilot Fusion is now GA across GitHub Enterprise.
  • Dynamic Multi-Model Switching: Automatically routes sub-tasks across Claude 3.5/3.7, GPT-4o, OpenAI o1, and Gemini.
  • Task Specialization: Fast models handle syntax, documentation, and unit tests; deep reasoning models handle refactoring and AST analysis.
Architectural Impact
  • Zero Model Lock-in: Eliminates enterprise dependency on a single AI lab or provider.
  • Cost & SLA Optimization: Maximizes quality while keeping inference cost and latency bounded.
  • Model Routing Abstraction: Internal tools must follow this design pattern: decouple agent orchestrators from model endpoints.
Feature number one in the recap is Copilot Fusion, which has reached General Availability. Fusion is the intelligent routing brain. Instead of forcing developers to pick one model for everything, Fusion routes automatically: fast, lightweight models for routine boilerplate and lint fixes, and heavy reasoning models like Claude 3.7 or o1 for complex multi-file architectural changes. For our architecture team, this validates our approach: never hardcode to a single LLM API.
Feature Announcement #2

The Copilot App & Canvases

Expanding beyond the IDE sidebar into a dedicated workspace

Copilot App & Canvases
  • Dedicated Canvas Space: Visual interactive canvas connecting issues, PRs, architecture diagrams, and design tokens.
  • Multi-Session Orchestration: Run and monitor 5+ agent sessions concurrently across different projects.
  • Figma & Design Ingestion: Ingests UI mockups and translates them directly into component hierarchies.
Cross-Surface Session Continuity
  • Persistent Cloud State: Sessions live in the cloud, not on developer laptops.
  • Seamless Surface Handoff: Start an investigation on mobile, refine on Web canvas, execute in terminal CLI, and finalize in VS Code.
  • No Build Context Lost: Terminal history, hot reproduction sandboxes, and git diffs remain synced.
Feature number two: The dedicated Copilot App and Canvases. GitHub realized that a narrow 300-pixel chat sidebar inside VS Code is too cramped for orchestrating full features. The Copilot App gives developers a full canvas where they can visually link Figma designs, Jira/GitHub issues, and architecture specs. And with cross-surface continuity, sessions are persistent in the cloud—allowing engineers to start work on a phone or browser and pick it up in VS Code without re-running builds.
Feature Announcement #3

Copilot Projects (Public Preview)

Cross-repository orchestration for distributed systems

Breaking the Single-Repo Barrier
Agents historically failed when microservices were split across multiple repositories. Copilot Projects introduces cross-repo context trees, allowing a single task to generate synchronized PRs across contract repos, backends, and frontend consumers.
Context Graphs
Maps API contracts and dependency relationships between repos automatically.
Synchronized PRs
Generates linked PR chains with shared trace IDs across downstream consumers.
Unified Testing
Runs end-to-end integration tests in cloud sandboxes across the linked branch matrix.
Announcement number three is Copilot Projects, now in public preview. This solves the biggest pain point our architecture team has voiced: microservice fragmentation. Instead of having to prompt an agent separately in three different repositories, Copilot Projects maintains a cross-repository context graph. It can execute a feature end-to-end: updating a shared Protobuf schema, adjusting the backend service, and updating the client consumer in one atomic flow.
Feature Announcement #4

Copilot Automations

Event-driven autonomous background workflows

Signal-Triggered Agents
  • Production Event Triggers: Responds autonomously to monitoring alerts (Datadog, Sentry, CloudWatch) or newly opened issues.
  • Reproduction in Sandbox: Spins up a clean cloud container, checks out code, and attempts to reproduce the stack trace.
  • Draft Fix & Unit Tests: Authors candidate patch, adds regression unit test, and opens a draft PR with full reproduction logs.
Architectural Guardrails
  • Credit & Rate Limits: Team-scoped dollar credit limits prevent runaway agent loops.
  • Sandbox Isolation: Agents run in restricted micro-VMs with zero production write access.
  • Human in the Loop: Autonomous PRs require human review unless specifically designated on safe paths.
Feature four is Copilot Automations. This moves Copilot from a developer-driven tool to an event-driven system. When an alert fires in production or a high-priority bug is filed, Copilot Automations can immediately spin up an isolated sandbox, reproduce the bug against integration tests, write a fix with a new unit test, and have a draft PR ready for human review before the on-call engineer even opens their laptop.
Feature Announcement #5

Code Review "Max" & Agent Merge

Adversarial multi-model code review and autonomous conflict resolution

Code Review "Max" (Public Preview)
  • Multi-Model Adversarial Review: Multiple models critique incoming diffs from distinct perspectives (security, performance, architectural invariants).
  • Deep Multi-File Context: Scans not just the diff, but the entire call graph and downstream callers.
  • Security Taint Analysis: Traces user-controlled inputs across boundaries to prevent injection vulnerabilities.
Agent Merge & Auto-Rebase
  • Semantic Conflict Resolution: Agents understand code syntax to resolve non-trivial git merge conflicts automatically.
  • CI Failure Remediation: When a PR fails unit tests, Agent Merge diagnoses the failure, patches the branch, and re-triggers CI.
  • Path-Scoped Approvals: Admins grant auto-approval permissions on designated safe file patterns (docs, schemas).
Feature five: Code Review 'Max' and Agent Merge. Code Review Max introduces deep, multi-model adversarial reviews for high-risk PRs. Instead of a superficial linter, it examines full call graphs and security taint paths. Meanwhile, Agent Merge eliminates one of our biggest developer time-sinks: rebasing stale branches and fixing broken CI runs. The agent automatically repairs semantic conflicts and re-runs the tests.
Feature Announcement #6

Usage-Based Enterprise Contracts

Shifting from rigid per-seat licensing to consumption credit pools

The Per-Seat Dilemma
  • Traditional licensing forced enterprises to purchase flat monthly licenses per developer seat.
  • Did not account for variable agent compute, heavy reasoning models, or sporadic background automation workloads.
New Usage & Credit Model
  • Consumption-Based Option: Enterprise customers can choose a unified consumption contract backed by AI credits.
  • Consolidated Pool: Shared dollar pool covers GitHub Actions runners, Copilot cloud sandboxes, and advanced model inferences (e.g. Code Review Max).
  • Existing Plans Protected: Teams on traditional per-seat subscriptions can remain on their existing structure.
Feature six is a major commercial and administrative shift. GitHub introduced an enterprise contract option centered around AI usage credits rather than strictly per-seat licenses. This is crucial as we deploy autonomous agents: agents don't have seats; they consume compute. A unified dollar-based credit pool allows us to balance spend fluidly between CI runners, cloud sandboxes, and agent tasks.
Feature Announcement #7

Rebuilding Git for 45B+ Actions

Underlying platform engineering to withstand agent write storms

Lockless Ref Updates
Eliminated branch write locks in the core Git storage layer, allowing thousands of concurrent agent PRs and branch updates without contention.
Actions Workflow Lockfiles
Cryptographic SHA pinning for all GitHub Actions dependencies, locking CI supply chains against tag tampering and upstream compromise.
Multi-Cloud Runners
Native scheduling of GitHub Actions Linux jobs directly inside customer AWS and Azure VPCs with direct access to private corporate endpoints.
Finally, the keynote recap highlighted GitHub's deep infrastructure investments. Git was never designed for millions of AI agents committing simultaneously. GitHub re-engineered the underlying ref storage to be completely lockless, eliminating write contention. And on CI/CD, Actions Workflow Lockfiles give us zero-trust supply chain protection, while Multi-Cloud Runners let us execute builds directly inside our AWS VPC.
